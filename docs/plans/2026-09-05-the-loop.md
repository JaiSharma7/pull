# The loop — fifty PRs in five days

Status: **approved 2026-09-05**, full scope, three sessions. Written from the market report
of the same date and a code audit; the "Corrections" section is what the audit changed.

## Context

Jai commissioned a 30-page market report (GPT-6 Astra, 5 Sept 2026, pinned to `main`
at `0651c24`) over 51 microlearning, study, language and workplace-learning products,
and wants What a Pull to become the free super app that absorbs their best mechanics.
The report's own conclusion, which this plan follows: the winning shape is **one
connected loop** — discover or import → understand the evidence → practice → revisit →
apply — not every competitor's button on one feed. Pull already has the pieces; the
gaps are the connections between them.

Decisions already taken with Jai:

- **All of it free.** No tier is added; the terms/roadmap disagreement on "a paid tier"
  is reconciled toward all-free in the docs pass.
- **Law 2 bends once, bounded and ledgered.** Private generation from an import and
  embedding of imported highlights run as _generation-time_ jobs under the existing
  quota (3 fast/day, 50 ceiling) plus a new global daily spend cap; every call writes
  `cost_ledger`. Say It Back stays self-graded. Laws 1, 4, 5, 6, 7 stay intact.
- **Deploy each day.** After a schema PR merges, apply its migration to the hosted
  project (`zjvfwhjwaytyogdxeddo`), redeploy `worker` if `supabase/functions` changed,
  let Vercel build `main`, and run the PR's live check.
- **Pace: 10–15 PRs a day.** The repo has done this (12 merges on 31 Aug, 33 on 1 Sept,
  17 on 3 Sept); the 3 Sept burst was ten parallel PRs integrated by one PR (#73) that
  then needed six fix rounds. So the roadmap is cut into **one-concern PRs of 1–4 hours'
  build**, in lanes, so three sessions can run in parallel without colliding.

## Corrections the Plan agent verified in code (the sketch changed here)

1. `get_due_reviews` returns only `question` = the prompt (`20260829130514:114-160`) and
   `scripts/smoke-read-path.sql:69` needs the top level to stay an **array**. Widen it
   once (activity engine) and cache that shape (packs), so packs follow the engine.
2. `grade_recall` and `record_interrupt` cannot be widened with `create or replace`
   (overload → "function is not unique" from `record_interrupt`'s positional call).
   `drop function` the old signature first, as `20260829135423` did for `get_feed`.
3. **No `is_guest()` clause on `recall_events`** — guests grade today; refusing them
   breaks Review for guests. Guest clauses belong on `commit_import` and Studio.
4. The client cannot insert the works/summaries/pulls triple; `commit_import` must be
   `security definer` and is the only non-pipeline pull writer.
5. `summaries unique (work_id, version, author_id)`: one private summary per (work,
   reader); a second import of the same book appends pulls at `max(ordinal)+1`.
6. `works` is world-readable and `slug` unique → an imported title would be enumerable
   at `/rest/v1/works`. Tighten to "a readable summary sits behind it"; every existing
   reader of `works` already filters harder. `20260831013500` re-granted named columns,
   so any new `works` column needs an explicit grant.
7. `get_feed` pool is `published + public` so imports never enter the feed;
   `known_ideas` reads all of the reader's embedded `knowledge_states`, so embedded
   private pulls shape the Delta — exactly the intent. `og/index.ts` uses the anon key,
   so a private pull cannot be unfurled.
8. Pipeline target: `kind`, `text`, `url`, `title`, `rights_status`, `author`
   (`pipeline.ts:571-693`). `template.upsertWork` keys on `content_hash` and would
   create a second `works` row for an imported book unless taught to adopt
   `target.work_id` (guarded by "requester authored a summary on it").
9. An embed-only job cannot jump straight to `embed`: `moderate.after = [artwork,
embed]` would wait forever. Path is `resolve_identity → embed → publish` with
   `jumpTo` on both hops; `jumpFor` reads `embed`'s persisted output; `NEEDS` for
   `embed`/`publish` add `resolve_identity`.
10. A new `relate` node must be added to `PROVIDER_STEPS` or its cost never reaches the
    ledger.
11. User questions are a **separate table** (a partial unique on `quiz_questions` would
    break the pipeline's `onConflict` upsert).
12. BAML changes ripple through four fixed places: `canonical_summary.baml`, `BOUNDS`
    in `packages/prompts/scripts/export.mjs:181-187`, `schema.test.ts`,
    `questionsToWrite` (`pipeline.ts:463`). Gemini has no map type → `rationale` is an
    array of `{distractor, why}`.
13. `Interrupt` gets a `FeedRow` with no question; fetch it on demand (≤3/session)
    through RLS and render free recall until it arrives, rather than re-stating
    `get_feed`.
14. `lib/offline.ts` is `openDB('what-a-pull', 1)`; v2 must drop and recreate `pulls`
    (old rows cannot be attributed to a user). `fake-indexeddb/auto` is the harness.
15. `notes` has no `client_mutation_id`; the path apply step needs one.
16. `supports` ripples to `packages/schemas` `RELATION_KINDS`, `pnpm db:types`,
    `lib/types.ts` `GraphEdge.kind`, `Source.tsx` `RELATION_LABEL`.
17. `get_feed(p_recipe_id)`: drop the six-arg signature; the client's named-arg calls
    keep working because the new parameter defaults.
18. Anonymous → permanent conversion is supported by GoTrue (`updateUser({ email })`
    keeps the id) but contradicts `App.tsx:1075,1108`, `privacy.md` and `terms.md` §2.
    A product decision, flagged; not built unless Jai approves.
19. Audio prefs live in localStorage (voices are per device), not `preference_profiles`.
20. `speechSynthesis.pause()` is unreliable on Chrome Android: treat pause as cancel +
    remembered utterance boundary.

Six more, from the review of this plan (PR #75):

21. `search_catalogue` requires `visibility = 'public'` in its `matched`, `near` and
    source queries (`20260901020000:107-108, 147-148, 185-186`), so an import would be
    unfindable by search. A private-results branch is its own PR (2g) and the release
    test's last hop depends on it.
22. Checking `spend_today()` before a provider call is not a cap: two workers read the
    same number and both spend. The cap is a transactional **reservation** — reserve a
    worst-case amount under a global lock, settle it when the ledger row lands — and
    `enqueue` checks spend plus open reservations.
23. Imported works are **per reader**, not shared by title. Two different books called
    "Selected Essays" would otherwise share a catalogue identity and each other's
    bylines. The slug carries a hash of (reader, title, author).
24. A remembered highlight is due **now**, not tomorrow: "Remember this" is an explicit
    ask to practise, and the release test walks straight from it into Review.
25. A queued recall write from before the upgrade has no mutation id; the IndexedDB v2
    upgrade assigns and persists one so its first replay is already de-duplicable.
26. Dedupe is scoped to the book: the content hash covers the work identity and the
    text, so the same passage in two books is two highlights.

## Lanes and the parallelism rules

| Lane         | Contents                                                | Rule                                                                                              |
| ------------ | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `S` schema   | any PR adding a migration, its db test, `pnpm db:types` | **strictly serial** (ordered timestamps; one regenerated types file). One session owns it.        |
| `C` client   | `apps/web` only                                         | parallel, except PRs marked **hot** (`App.tsx`, `Feed.tsx`) go one at a time                      |
| `P` pipeline | `supabase/functions`, `packages/prompts`                | parallel with C; serial with itself (one generated export tree); each ends with a worker redeploy |
| `U` ui-kit   | `packages/ui`                                           | serial with itself (all touch `PullCard`)                                                         |
| `D` docs     | `docs/`, `README.md`                                    | folded into the PR that makes the claim true; one reconciliation PR at the end                    |

Schema PRs carry their own `docs/privacy.md` / `docs/terms.md` / `docs/data-model.md`
lines. Every migration follows the `/migrate` skill: table + RLS + FK indexes in one
file, `pnpm db:reset`, `db:lint`, `db:test`, `db:types`, advisors clean.
